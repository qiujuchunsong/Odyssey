第四章总结：
    成果：每个应用拥有独立的虚拟地址空间（Sv39 三级页表），内核与用户共享跳板 trap.S 完成地址空间切换，
          6 个应用在各自页表下跑完，页错误能被内核捕获并杀进程，全部结束后优雅关机
    四次翻车，没有一次是逻辑 bug，全是"人为约定"：
      1. user/src/linker.ld 段间没对齐 4K → 两个段落在同一页 → 同一 VPN 被映射两次
      2. os/build.rs 内嵌的是 objcopy 的 .bin，而 ch4 的 from_elf 要的是 ELF
      3. 从 Windows 拷文件进 WSL 带出 7 个 *:Zone.Identifier 垃圾文件，应用数被数成两倍
      4. 改了 app 的 ELF 但没 cargo clean，内核里嵌的还是旧文件（cargo 0.3s 就"成功"了）
    学到的方法：
      1. 从最早的错误往下修 —— 106 个编译错误其实只有约 10 个根因，后面的多是前面的影子
      2. 断言是最好的调试器 —— map() 的 "is mapped before mapping" 直接点出 VPN 0x11
      3. 内核 bug 的第一嫌疑人是链接脚本 / 构建脚本 / 常量，不是算法
      4. 写完注释才算真懂 —— 写不出那一句话，说明还没懂
